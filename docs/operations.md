# 限流与定时清理

## 限流

所有入口共用一套数据库固定窗口限流器：`rate_limits` 表按 `scope + 身份` 计数，身份经 HMAC 处理，不落库明文 IP / 邮箱 / 用户 ID；多实例共享同一份计数，数据库不可用时自动退回进程内计数。超限的 API 返回 `429` 与 `Retry-After`，服务端函数返回 `RATE_LIMITED`。

| 场景                      | 维度          | 限额                          |
| ------------------------- | ------------- | ----------------------------- |
| 认证入口总计              | IP            | 300 / 分钟                    |
| 邮箱密码登录              | IP / 账号     | 20 / 10 分钟、10 / 15 分钟    |
| 注册                      | IP            | 10 / 小时                     |
| 重发验证邮件              | IP / 账号     | 5 / 15 分钟、3 / 小时         |
| 找回密码                  | IP / 账号     | 5 / 15 分钟、3 / 小时         |
| 重置密码 / 修改密码       | IP            | 10 / 15 分钟                  |
| 修改邮箱 / 删除账号       | IP            | 10 / 小时、5 / 小时           |
| 更新资料                  | IP            | 30 / 10 分钟                  |
| 其他认证接口              | IP            | 120 / 分钟                    |
| 管理端认证接口            | IP            | 60 / 分钟                     |
| 服务端函数（全部请求）    | IP            | 600 / 分钟                    |
| 服务端函数（登录用户）    | 用户          | 240 / 分钟                    |
| 管理端请求（管理员）      | 用户          | 240 / 分钟                    |
| 创建临时邮箱              | 用户          | 30 / 小时                     |
| 创建长期邮箱              | 用户          | 10 / 小时                     |
| 删除邮箱                  | 用户          | 30 / 分钟                     |
| 邮件变更（已读 / 删除等） | 用户          | 120 / 分钟                    |
| 发信                      | 用户          | 10 / 分钟（另受每日额度限制） |
| 附件下载                  | 用户 / IP     | 60 / 分钟、120 / 分钟         |
| Telegram 操作             | Telegram 用户 | 30 / 分钟                     |
| Telegram 绑定令牌         | 用户          | 5 / 小时                      |
| 初始化管理员              | IP            | 5 / 小时                      |
| Resend / Telegram Webhook | IP            | 600 / 分钟                    |
| 清理任务                  | IP            | 20 / 分钟                     |
| 其他 API                  | IP            | 120 / 分钟                    |

认证限流在 Better Auth 处理请求之前执行，密码类端点同时按账号计数；Webhook 仍需通过各自签名校验。限流阈值集中在 `src/server/rate-limit.ts`。IP 维度依赖部署代理正确覆盖 `IP_ADDRESS_HEADERS`（见 `.env.example`），直接暴露 Node 时务必配置。

升级部署会新增 `rate_limits` 表并移除旧的 `renew_count` 列：开发库执行 `bun run db:push`，线上执行 `bun run db:migrate`。

## 定时清理

`GET|POST /api/cron/cleanup` 会执行：

- 删除未收件且已过期的临时邮箱及其邮件、附件（有效期内收到邮件的临时邮箱会保留）；
- 删除超过保留期的收件与已发送记录；
- 清理到期的地址冷却记录；
- 清理 30 天前的收件日志、180 天前的审计日志；
- 清理过期的会话、验证记录与限流计数器；
- 删除对应的 S3 对象（批量删除，失败时保留数据库行以便下次重试）。

鉴权：仅接受 `Authorization: Bearer $CRON_SECRET`；未设置 `CRON_SECRET` 时接口一律拒绝。

- **Vercel**：`vercel.json` 已配置每天 03:00 调用；Vercel 会自动带上 `CRON_SECRET`。
- **VPS / Docker**：用系统 cron 或容器编排的定时任务调用，例如：

  ```
  0 3 * * * curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://mail.example.com/api/cron/cleanup
  ```
